# Rules

Every rule the binary runs, with what it checks, the goal it approximates
and the precision a judged round measured. Generated by `cargo xtask
rules-doc` from `sightline explain --json`; `sightline explain <id>` prints
one rule's record at the terminal. Never edit this file by hand.

A rule's **family** names what it prices: trust (declared contracts against
what callers prove), surface (repeats, clumps and complexity), context (what
a reader must ingest), perf, tests, and checker (the type checker's own
verdicts). Its **tier** is how its findings are proved (proved, indexed or
heuristic). Its **posture** is what `gate` does with them: ratchet blocks
what a change adds over the committed baseline, report never blocks. Its
**scope** says which gate runs it: a file rule reads one file and runs in
the fast gate on every edit; a repo rule reads the whole tree and runs only
under `audit` and `gate --full`, so a fast gate cannot see what a repo rule
would block on.

**Precision** is the judged sample, real findings over findings read, with
the 95% interval that sample supports; the report ranks on a lower bound of
it, so a rule judged on five sites sits below one judged on two hundred at
the same fraction. `architecture.md` explains the rounds. Ids are permanent;
a Rust reading shares its Python sibling's id and slug.
